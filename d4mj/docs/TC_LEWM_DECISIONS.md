# Decisions, source fidelity, and proposed hyperparameters

Date: 2026-09-05. This is a **proposal ledger**, not a record that these settings have been approved by an experiment. `Requirement` denotes an interface or validity constraint; `Source-derived` denotes a proposed value with identified provenance; `Adaptation` denotes our proposed engineering/research choice; `Open` denotes work required before the corresponding run. None denotes demonstrated Craftax performance.

## Fully exposed pilot recipe

Every row is a proposed default or an explicit required manifest field. A field not yet resolved must make the launch preflight fail; neither “default from library” nor an undocumented value in a launcher counts as resolved. Raw and TC recipes differ only in `variant` (`raw` or `tc`), which selects the regularization target, and output paths. M0–M3 fields are resolved in `d4mj/recipes/lewm_mamba_{raw,tc}.json`; later-phase fields below remain proposals, not hidden active defaults.

## Open items that must not become accidental defaults

1. **Dataset selection:** exact immutable archive manifest, collection-policy checkpoints and training access, episode split hashes, counts by role/event/termination, preprocessing and environment versions. Choose from audited existing stores; no dataset name inferred from a successful artifact directory.
2. **Source construction:** pin `stable_pretraining`'s ViT helper or an inspected equivalent and its Transformers version. Diff the actual resolved model against the explicit Tiny proposal. Pin C-M2 operations and imported dependency versions. The current general requirements file is not that lock.
3. **Memory feasibility:** actual B128 joint loss with source-scale SIGReg and both BN projectors on the target GPU. If activation checkpointing is insufficient, report the measured bottleneck. A correct recompute/embedding-gradient method needs its own full-batch output/gradient/BN proof before substituting; otherwise choose a new statistical-batch recipe explicitly.
4. **Benchmark access:** choose the exact D3 Craftax protocol and whether an online comparison is worth funding. A 201M-parameter published comparator and an offline expert archive cannot be made matched by renaming a plot. No arbitrary Dreamer score threshold is sealed here.
5. **Long-horizon feasibility:** H16 is a target, not an accepted capability. Larger recursive depth, stochastic dynamics, latent width, and centering window may need revision only after the failed observable is identified.

## Change discipline

Create a resolved recipe before allocating a training run. Include every value above, implementation/source digests, data identity and all open items relevant to that run. A code change, shape change, loss reduction change, normalization change, training-access change or altered statistical batch creates a new recipe ID. Do not resume an old optimizer into that new recipe as though the experiment were unchanged.

Pure output-path changes and resume of the identical schedule are permitted by the loader; additional training beyond the sealed budget is a new extension record with its parent checkpoint. Raw/TC comparisons must replay the changed recipe on both sides. A performance-based architecture decision after the screen is reported as DEV selection; FINAL stays sealed.
